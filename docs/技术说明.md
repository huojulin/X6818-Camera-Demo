# X6818 高速运动相机 Demo 技术说明

> 板载自包含方案 · 采集 / 解码 / 显示 / 录制 / 回放 本地闭环

## 一、项目背景与目标

本 Demo 是“高速运动相机原型 v1.0”课题在 X6818 开发板上的落地实现。目标是一套完全板载自包含的相机系统：USB 相机采集、实时解码显示到 LCD、触摸屏控制拍照 / 录像 / 回放 / 退出、零编码 MJPEG-AVI 本地录制、板载 mplayer 直接回放。系统不依赖 PC / VM、不依赖 WiFi 回传，全部在开发板本地闭环运行；程序启停由板子触摸屏按钮处理，断电复位后一条脚本即可拉起全部功能。

## 二、硬件与运行环境

| 项目 | 规格 |
|---|---|
| 开发板 | X6818（S5P6818，Cortex-A53 八核，1GB DDR3） |
| 显示 | LCD 1024×600，`/dev/fb0`，32bpp BGRA |
| 相机 | USB 相机（gspca_zc3xx / UVC，输出 MJPEG 或 YUYV） |
| 输入 | 触摸屏 `/dev/input/event1` + 物理按键（可选） |
| 媒体存储 | `/root/camera/`（拍照 `shot_*.jpg`、录像 `rec_*.avi`） |
| 交叉编译 | `arm-linux-gcc 4.7.4`（VM Ubuntu 16.04） |
| 板子解码 | rootfs 自带 libjpeg（mplayer 依赖） |

## 三、系统架构

系统由外设、板载处理、输出与输入三部分构成：USB 相机作为采集源，经板载相机管线（采集 · 解码 · 双缓冲显示）输出到 LCD；触摸屏向板载发送控制指令；录制文件写入 `/root/camera`；PC 导出（转 mp4）为可选能力，通过 WiFi / 以太网进行，不影响板载主流程。（完整可视化架构图与数据流水线图见仓库 `docs/architecture.svg`、`docs/pipeline.svg` 与 `web/camera_demo.html`）

| 环节 | 组成 | 说明 |
|---|---|---|
| 采集源 | USB 相机 | MJPEG / YUYV 输出 |
| 板载处理 | V4L2 采集 + libjpeg 解码 + 双缓冲显示 | 实时取景 |
| 控制 | 触摸屏 UI（拍照 / 录·停 / 回放 / 退出） | 单实例守卫防多进程抢 fb0 |
| 录制 | MJPEG-AVI 零编码封装 | 首帧到达才建文件，杜绝空文件 |
| 回放 | 板载 mplayer 原生解码 | 无 VPU，走 MJPEG 路线避免黑屏 |
| 存储 | `/root/camera` | 程序启动自动创建 |

## 四、数据流水线

实时相机帧按以下链路处理：V4L2 采集 MJPEG 帧 → libjpeg 解码为 RGB → 双缓冲写入 fb0 显示；与此同时，触屏可触发拍照或录像，录制文件由板载 mplayer 直接回放。

1. **V4L2 采集**：打开 `/dev/videoX`，协商 MJPEG（回退 YUYV），mmap 流式取帧。
2. **libjpeg 解码**：JPEG 解成 RGB（可选 libjpeg-turbo NEON 加速）。
3. **双缓冲显示**：离屏缓冲绘制，每帧末尾 memcpy 到真实 fb0，消除闪烁。
4. **AVI 零编码录制**：MJPEG 帧直接封 AVI 容器，写 `/root/camera`。
5. **板载回放**：mplayer 原生解码 AVI，配合实测帧率与索引修正完整播放。

## 五、功能模块说明（phone_view.c 关键代码）

### 1. V4L2 相机采集
`cam_init` / `cam_capture_frame`：打开 `/dev/videoX`，协商 MJPEG 格式（回退 YUYV），mmap 流式采集，逐帧取出 JPEG 数据。

### 2. MJPEG 解码
使用 libjpeg（优先 libjpeg-turbo NEON）`jpeg_decompress` 把 JPEG 解成 RGB；YUYV 源先软件转码再走同一显示路径。

### 3. 双缓冲帧缓冲显示
`fb_init` / `fb_flush`：真实 fb0 用 mmap，另开离屏 malloc 缓冲；所有绘制写离屏，每帧末尾一次性 memcpy 到 fb0，彻底消除按钮闪烁与撕裂。

### 4. MJPEG-AVI 零编码录制
`avirec_*`：MJPEG 帧直接封装进 AVI（RIFF/AVI/LIST/hdrl/movi/idx1），首帧到达才建文件（杜绝空文件）；停止时回填 avih/strh 并写入实测帧率 `.fps` 旁注。

### 5. 触摸屏 UI 控制
`touch_thread` / `draw_bottom_buttons` / `hit_button`：读 event1，底部四按钮（拍照 / 录·停 / 回放 / 退出），带单实例守卫避免多进程抢 fb0。

### 6. 板载回放
`start_board_playback`：取 `/root/camera` 最新 `shot_*.jpg` 或 `rec_*.avi`；照片解码铺满 + 触摸返回，录像用 mplayer 原生解码 + 实测帧率 + 索引修正。

## 六、编译与部署

### 6.1 交叉编译（VM 端）
```bash
cd src
make clean && make          # 产出 arm 可执行 phone_view
# 可选 NEON 加速：先准备 libjpeg-turbo/lib/libjpeg.a，Makefile 自动优先链接
```

### 6.2 固化到板子（VM → 板子，ext4 持久，复位不丢）
```bash
bash install_to_board.sh <板子IP>
# phone_view → /usr/bin/phone_view，脚本 → /root/*.sh
```

### 6.3 仅更新二进制（已固化过更快）
```bash
# 板子串口
killall phone_view
# VM 端（冒号前不要有空格）
scp ../src/phone_view root@<板子IP>:/usr/bin/phone_view
# 板子复位后只需一条
sh /root/boot_cam.sh
```

## 七、现场演示步骤（板子触屏操作）

1. 串口（或 SSH）执行 `sh /root/boot_cam.sh`（自动起 sshd、按真实 major:minor 建相机节点、起 phone_view）。
2. LCD 显示相机实时画面，底部四个触摸按钮：拍照 / 录·停 / 回放 / 退出。
3. 点【录】开始录制 → 再点【录·停】停止，自动存 `/root/camera/rec_*.avi`。
4. 点【拍照】把当前帧存为 jpg 到 `/root/camera/`。
5. 点【回放】板载 mplayer 播放最新录像（或显示最新照片，触摸任意处返回）。
6. 点【退出】干净退出进程。

> 提示：本板无硬件视频解码器（VPU），H.264 解不动会黑屏；板载回放走 MJPEG-AVI 原生解码路线，配合实测帧率旁注与 AVI 索引修正，可完整流畅回放。

## 八、技术亮点与难点

| 要点 | 说明 |
|---|---|
| 无 VPU → 放弃 H.264 | 板子无硬件解码器，预装 mplayer 软解 H.264 黑屏；改用 MJPEG-AVI 原生解码回放。 |
| AVI 索引偏移修正 | 索引 `dwOffset` 基准改为相对 movi 数据起点（规范值），修正老 mplayer 错位只放开头。 |
| 2 字节帧对齐 | 帧 padding 按 AVI 标准 2 字节对齐，兼容 1.0rc2 老 mplayer 的顺序读取。 |
| 双缓冲去闪烁 | 离屏缓冲 + 每帧 memcpy，消除单缓冲下的按钮闪动 / 撕裂。 |
| 零编码录制 | MJPEG 帧直接封 AVI，不依赖 ffmpeg / x264，板子即时可录。 |
| 无 udev / mdev 建节点 | 板子不自动建 /dev 节点，setup_cam.sh 按真实 major:minor 手动 mknod 并排除显示层。 |
| 自包含部署 | 程序启动自动 mkdir /root/camera；复位后一条 boot_cam.sh 拉起全部。 |

## 九、总结

本 Demo 在资源受限的嵌入式板子上，用纯 C 单文件（约 2000 行）实现了采集、解码、显示、录制、回放的全链路闭环，并针对“无 VPU、无 udev、老 mplayer”等硬件约束做了针对性处理。整套方案完全板载自包含、可复位恢复，适合作为高速运动相机课题的演示与教学样例。
